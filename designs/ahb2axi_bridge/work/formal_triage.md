# Formal counterexample triage — ahb2axi_bridge

Counterexamples analysed: 9. Causes: A = RTL wrong, B = checker wrong, C = specification unclear, E = an environment obligation missing from verif/formal/nnc_env.sv. The designer decides; nothing was changed.

## CHK-001 — most likely **A_rtl_wrong**

| Part | Content |
|---|---|
| What happens | Through step 10 the trace contains many AHB transfers, some of them illegal (AHB address/control changes while HREADY=0, for example steps 8->9 and 11->12). There is one B handshake at step 7 with BRESP=3 (DECERR). At step 10 a NONSEQ Device-E write (HPROT=5) is accepted. At step 11 the bridge drives o_ahb_hresp=1 and o_ahb_hreadyout=0, which is the first ERROR cycle; the manager is presenting a NONSEQ read with HREADY=0. At step 12 the manager presents a NONSEQ write (HWRITE changed 0->1 while the transfer was waited). The bridge again drives hresp=1 and hreadyout=0. This is a second 'first' ERROR cycle where an ERROR with HREADYOUT=1 is required, so a_CHK_001 fails at step 12 (chk001_prev_first=1 but hresp&&hreadyout=0). Reset is asserted at step 13. |
| Specification says | spec/AHB2AXI_Bridge_Design_Specification.md:494 "AHB ERROR timing follows REF-001 §5.1: the first ERROR cycle has HREADYOUT low and the second has HREADYOUT high." (rules.json AA-12-16). spec:270 o_ahb_hresp "ERROR follows two-cycle response" (AA-T1.7.2.2-07). spec:154 REQ-ERR-001 "...map to the AHB two-cycle ERROR response." |
| RTL does | rtl/m_ahb2axi_ahb_if.sv:91-101: when a data phase is valid and i_rsp_err=1, hreadyout=0 only while ~reg_err_second (lines 95-96), and reg_err_second is set at the next edge (lines 120-121). That gives a correct second cycle. Lines 104-105 then override it unconditionally: `if (i_ahb_hsel & i_ahb_htrans[1] & ~i_req_ready) o_ahb_hreadyout = 1'b0;`. At step 12 HSEL=1 and HTRANS=NONSEQ write. The controller is in ENUM_ST_AHB_RSP (reg_rsp_valid is held), so w_req_ready = ~w_wr_cmd_full (m_ahb2axi_ctrl.sv:568-572), and that is 0 here. The bridge therefore holds the current data phase low to backpressure the *next* address, which stretches the second ERROR cycle. |
| Checker does | verif/sva/nnc_chk_ahb.sv:65-69 registers chk001_prev_first = hresp && !hreadyout. Lines 72-75 assert (hresp || prev_first) |-> (prev_first == (hresp && hreadyout)). This means a first ERROR cycle must be followed by ERROR with HREADYOUT=1, and ERROR with HREADYOUT=1 must follow a first cycle. This matches the contract behaviour text and spec:494. |
| A_rtl_wrong | For: ahb_if.sv:104-105 forces HREADYOUT low whenever the next address phase cannot be queued, even during the second ERROR cycle. This directly breaks spec:494/AA-12-16. CHK-002 fails from the same lines with fully legal stimulus (see CHK-002). A subordinate must not extend the current data phase because of the next address phase. It must accept or register the address and wait-state that transfer's own data phase.<br>Against: In this particular trace the stall depends on the address phase at step 12 being a write (write command FIFO full). Had the manager kept the step-11 NONSEQ read stable, req_ready = ~w_rd_cmd_full, which is probably 1 (no read was accepted in the trace), and the second cycle would have been HREADYOUT=1. |
| E_environment_missing | For: The manager changes HWRITE (0->1) of a NONSEQ address phase between step 11 and step 12 while HREADY=0. It also changes address/control during waited NONSEQ phases at steps 5->6 and 8->9. AHB5 (IHI 0033C, the interface named in spec:238/AA-6.1-01) requires the manager to hold the address and control of a NONSEQ/SEQ transfer stable until HREADY=1; after an ERROR it may only change HTRANS to IDLE. nnc_env.sv has no such assumption: ENV-04 (lines 174-178) covers only HWDATA/HWSTRB and ENV-05 (lines 180-185) covers only SEQ/BUSY.<br>Against: The defect sits in the RTL (lines 104-105) and does not depend on the manager violation. A legal manager that presents and holds a NONSEQ write during the first ERROR cycle while the write command FIFO is full would see the same stretched second cycle. The spec's ERROR timing rule has no exception for back-pressure. |
| Options | (1) RTL: remove the next-address stall from the current data phase in m_ahb2axi_ahb_if.sv:104-105. Capture an address phase that cannot enter the controller in a one-entry holding register, then wait-state that transfer's own data phase. Keep the second ERROR cycle (and IDLE/BUSY data phases) at HREADYOUT=1. (2) Separately, and supported by AHB5 IHI 0033C (AA-6.1-01): add an env assumption that address/control of a waited NONSEQ/SEQ address phase to this subordinate stay stable until HREADY=1, except for a change to IDLE after an ERROR first cycle. Re-run afterwards: with option 2 alone CHK-001 may still fail through the same RTL lines (a held write with the write command FIFO full). |

## CHK-002 — most likely **A_rtl_wrong**

| Part | Content |
|---|---|
| What happens | Step 1: NONSEQ INCR8 write, HPROT=28 (Normal Write-back, eligible), accepted. Step 2: IDLE with HSEL=1 and HREADY=1; the write gets its early OKAY (HREADYOUT=1). Step 3: IDLE with HSEL=1 and HREADY=1, which is the antecedent. Step 4: the manager presents a NONSEQ read. The bridge drives o_ahb_hreadyout=0 in the data phase of the step-3 IDLE transfer, and ENV-03 forces HREADY=0. a_CHK_002 fails at step 4 because the IDLE transfer did not get a zero-wait OKAY. |
| Specification says | spec:312 "A transfer is accepted ... when HSEL, HREADY and HTRANS[1] are all 1 ... BUSY and IDLE do not create AXI traffic" (AA-T1.7.3.1-01/-03). spec:238 IF-001 is an AHB5 IHI 0033C Subordinate (AA-6.1-01); AHB5 requires a zero-wait OKAY to IDLE/BUSY. contract.json CHK-021 expected (line 840): "IDLE and BUSY data phases complete in one cycle with o_ahb_hreadyout=1 and o_ahb_hresp=0." |
| RTL does | The write command written at step 1 becomes visible (FIFO empty flag registered, m_vlsit_sfifo_rd.sv:143-151) at step 3. The controller pops it in IDLE and moves to ENUM_ST_WR_CAPTURE; at step 4 o_axi_arcache=11 confirms reg_cmd_prot was loaded. In WR_CAPTURE, w_req_ready is 0 for a read (m_ahb2axi_ctrl.sv:574-578). m_ahb2axi_ahb_if.sv:104-105 `if (i_ahb_hsel & i_ahb_htrans[1] & ~i_req_ready) o_ahb_hreadyout = 1'b0;` then pulls HREADYOUT low, although no data phase is pending (reg_data_phase_valid was cleared at step 2) and the current data phase belongs to an IDLE. |
| Checker does | verif/sva/nnc_chk_ahb.sv:79-82: (hsel && hready && htrans in {IDLE,BUSY}) |=> (hreadyout && !hresp), disabled during reset. This is the contract behaviour exactly. |
| A_rtl_wrong | For: The stimulus is legal: an INCR8 burst ends early with IDLE (explicitly covered by spec:317 and CHK-026), followed by an ordinary NONSEQ read, and HREADY follows HREADYOUT as ENV-03 requires (nnc_env.sv:168-172). The only source of HREADYOUT=0 is ahb_if.sv:104-105, which back-pressures the next address by extending the current IDLE data phase. AHB5 does not allow this.<br>Against: None found. The spec's buffering allowance (spec:488 "AHB waits subject to buffering contract") does not permit wait states in an IDLE data phase. |
| B_checker_wrong | For: The checker samples hsel/hready/htrans directly; one could ask whether 'IDLE accepted' needs a data-phase owner.<br>Against: The AHB data phase of an IDLE with HSEL=1 and HREADY=1 belongs to this subordinate, and contract CHK-021 requires one-cycle OKAY. The checker matches the spec. |
| Options | RTL fix in m_ahb2axi_ahb_if.sv:104-105 (shared with CHK-001): accept or register the NONSEQ/SEQ address phase into a one-entry pending register when the controller is not ready, and insert the wait states in that transfer's own data phase. Never drive HREADYOUT=0 during an IDLE/BUSY data phase or during the second ERROR cycle. No checker or environment change is supported. |

## CHK-005 — most likely **A_rtl_wrong**

| Part | Content |
|---|---|
| What happens | Long trace (16 steps). AWREADY is 1 at steps 4-9 and 0 from step 10 on. At step 10 a SEQ write with HPROT=89 (HPROT[6]=1, which must be rejected) is accepted, and at step 11 a SEQ write to 0xFFFFFFFD with HSIZE=1 (misaligned, must be rejected) is accepted. Both enter the write command FIFO. The failure edge lies in steps 11-14, where o_axi_awvalid=1 and i_axi_awready=0 at t but VALID or the AW payload differs at t+1. The AW columns are truncated in the provided counterexample, so the exact edge and field cannot be read from the trace. |
| Specification says | spec:216 "AXI VALID and payload remain stable until READY handshake." (AA-5.4-04). spec:322 "AXI4 VALID and payload shall remain stable until READY handshakes." spec:488 "Hold VALID/payload stable until handshake" (AA-12-10). spec:313 misaligned and HPROT-reserved transfers "return AHB ERROR with no AXI request for the rejected transfer". |
| RTL does | In ENUM_ST_WR_SINGLE the AW payload is selected by reg_burst_fallback (m_ahb2axi_ctrl.sv:688-699): reg_cmd_* when 0, reg_burst_*[reg_burst_widx] when 1. reg_burst_fallback is set by `if (w_cap_stop) ... reg_burst_fallback <= 1'b1;` (lines 859-862) in every state. w_cap_stop = w_burst_term | (~w_wr_cmd_empty & ((w_cap_cmd_htrans != 2'b11) | ~w_cap_cmd_wr | w_cap_cmd_err)) (lines 513-516) is not gated by WR_CAPTURE. Rejected beats are still pushed into the write command FIFO (line 456: w_wr_cmd_wr_en = w_req_hs & w_req_wr, with no ~w_input_err). So while a single write sits in WR_SINGLE with AWVALID=1 and AWREADY=0, a queued non-SEQ or erroneous entry at the FIFO head flips reg_burst_fallback 0->1. At the next edge AWADDR/AWSIZE/AWCACHE/AWPROT switch from reg_cmd_* to reg_burst_*[widx]. No other AW payload source in WR_SINGLE/WR_BURST changes without a handshake (reg_cmd_* changes only at IDLE start, lines 818-822; reg_wr_id only at w_wr_rsp_rd_en, lines 895-899). |
| Checker does | verif/sva/nnc_chk_axi.sv:148-151: (awvalid && !awready) |=> awvalid && $stable(awid, awaddr, awlen, awsize, awburst, awcache, awprot), with disable iff (!i_rst_n_core). This matches the contract text. |
| A_rtl_wrong | For: The only RTL path that changes the AW payload of a pending WR_SINGLE request is the state-ungated w_cap_stop -> reg_burst_fallback update (ctrl.sv:513-516, 859-862), selected at lines 688-699. The same flag bug visibly corrupts AW in CHK-011/CHK-012. The AXI stability invariant (spec:216) is unconditional, and the spec requires out-of-profile AHB beats to be rejected with no AXI side effect (spec:313, 484-485).<br>Against: The AW columns are truncated, so the failing field and edge cannot be confirmed from the given trace; the mechanism is inferred from the RTL. |
| E_environment_missing | For: The stimulus breaks AHB5 manager rules that nnc_env.sv does not assume. Step 3 is a SEQ write after a NONSEQ read at step 2 (HWRITE changes inside a burst). HBURST/HSIZE/HPROT change between beats (step 9 HPROT=1 -> step 10 HPROT=89; spec:317 "HPROT remains constant throughout an AHB burst (REF-001 §3.8)"). The SEQ address at step 11 does not follow the burst. Address/control change during waited NONSEQ phases (steps 5-9). ENV-05 (nnc_env.sv:180-185) only requires ahb_in_burst for SEQ/BUSY.<br>Against: The spec requires the bridge to tolerate varying burst attributes (spec:317, CHK-025) and to reject misaligned or HPROT[6]=1 beats with ERROR (spec:313). AXI stability must hold whatever the AHB stimulus. The same fallback flip can be triggered by a queued NONSEQ head behind a SEQ head, without attribute changes. |
| Options | (1) RTL: restrict the w_cap_stop side effects (reg_burst_term_seen/reg_burst_fallback, ctrl.sv:859-862) to ENUM_ST_WR_CAPTURE (and to the IDLE start of an eligible burst), so reg_burst_fallback cannot change while an AW request is pending. Optionally keep rejected beats out of the burst-capture path. (2) Re-run with the AW columns dumped to confirm the failing field. (3) Separately, and supported by AHB5 and spec:317: add env assumptions for burst consistency (SEQ continues the same HWRITE/HSIZE/HBURST/HPROT burst, address/control held while waited). Do not use them to mask this failure; the AXI invariant is unconditional. |

## CHK-011 — most likely **A_rtl_wrong**

| Part | Content |
|---|---|
| What happens | Step 1: NONSEQ write, HBURST=5 (INCR8), HPROT=4 (HPROT[6:2]=00001, Device-E, not aggregatable), HADDR=0, HSIZE=2, accepted. Then IDLE. Step 4: the bridge issues AWVALID=1 with o_axi_awaddr=4095 (0xFFF), o_axi_awsize=5, AWLEN=0, AWBURST=INCR, WLAST=1. | Checker does | verif/sva/nnc_chk_axi.sv:132-135 compute aw_mask/aw_bytes/aw_end from awaddr[11:0], awlen and awsize. Lines 188-193 assert awlen<=15, a legal burst type, the WRAP rules, and for INCR aw_end <= 4096. This matches the contract and spec:150. |
| A_rtl_wrong | For: The stimulus is a plain legal Device-E write. The AW address and size disagree with the accepted beat (HADDR=0, HSIZE=2) while reg_cmd_* is correct (arsize=2 at step 4). | B_checker_wrong | For: None of substance; aw_end uses 32-bit arithmetic and the INCR condition from the contract.<br>Against: 4095 + 32 = 4127 > 4096 is a real 4 KiB crossing, and AWSIZE=5 is itself illegal for a 32-bit bus (spec:413). |
| Options | RTL fix in m_ahb2axi_ctrl.sv: gate w_cap_stop's update of reg_burst_fallback/reg_burst_term_seen (lines 859-862) to ENUM_ST_WR_CAPTURE, or give the IDLE-start clear (line 825) priority for non-eligible commands.
