## Assumptions

- Definitions used in all checks: an 'active edge' is a rising edge of i_clk_core with i_rst_n_core=1. An AHB address phase is 'accepted' at a rising edge with i_ahb_hsel=1, i_ahb_hready=1 and i_ahb_htrans[1]=1. Its data phase 'completes' at the first later active edge with o_ahb_hreadyout=1. i_ahb_hwdata and i_ahb_hwstrb belong to that data phase.
- Except in CHK-021 case (4), the testbench models a single-subordinate system with i_ahb_hready driven equal to o_ahb_hreadyout. In CHK-021, i_ahb_hready is driven on its own only while the bridge has no data phase in progress.
- Encodings: HTRANS IDLE=00, BUSY=01, NONSEQ=10, SEQ=11. HBURST SINGLE=000, INCR=001, WRAP4=010, INCR4=011, WRAP8=100, INCR8=101, WRAP16=110, INCR16=111. AxBURST FIXED=00, INCR=01, WRAP=10. xRESP OKAY=00, EXOKAY=01, SLVERR=10, DECERR=11.
- Legal-stimulus HPROT[6:2] patterns are limited to those the given rules list as supported: 5'b00000 (Device-nE), 5'b00001 (Device-E), 5'b00111 and 5'b01111 (Write-back, Non-shareable). Rejection tests use HPROT[6]=1 and the AHB5-reserved HPROT[5:2] codes {0100, 0101, 1000, 1001, 1010, 1011, 1100, 1101}, which cannot be in the supported list. Normal Non-cacheable and Write-through patterns are not exercised, because the excerpt does not say whether they are supported.
- AxCACHE mapping is read as each table row setting exactly one allocate bit, with the other bit 0: ARCACHE = {HPROT[4]&~HPROT[5], HPROT[4]&HPROT[5], HPROT[3], HPROT[2]} and AWCACHE = {HPROT[4]&HPROT[5], HPROT[4]&~HPROT[5], HPROT[3], HPROT[2]}.
- The 3-bit HBURST field has no reserved values in AHB5, so the 'reserved HBURST' rejection case cannot be stimulated; the other rejection causes are verified.
- The AXI subordinate model follows AXI4 subordinate rules (except in the CHK-036 injection phase): it returns i_axi_bid=o_axi_awid, i_axi_rid=o_axi_arid and i_axi_rlast=1, and is reset together with the bridge for coordinated-reset scenarios.
- AXI W beats are matched to AHB write beats by order, and B/R responses to AXI transactions by order. This is valid because the spec requires in-order handling and at most one outstanding transaction per direction.
- An AHB data phase may complete at the same rising edge as the R or B handshake it depends on (a same-cycle response path is allowed); checks require completion 'at or after' that handshake edge.
- Early termination of a fixed burst is driven by the manager placing IDLE or a new NONSEQ in the address-phase cycle right after the last captured beat's acceptance edge, so the termination is visible during that beat's data phase.
- Latency in CHK-034 is the AR/AW handshake edge minus the start edge. The start edge is the address acceptance edge for single requests, the final beat's acceptance edge + 1 for fixed bursts, and the edge at which the terminating transfer type is first sampled for early termination. The 6-cycle bound applies only with AXI READY held at 1 and the bridge otherwise idle.
- ID rotation order and the ID value after reset are not assumed. CHK-032 only expects that every legal ID appears within 2 x count consecutive transactions of the same direction, which follows from rotating through 0..count-1.
