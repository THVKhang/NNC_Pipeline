| Part | Content |
|---|---|
| Specification says | spec/rv_timer_Design_Specification.md:674 (D-016, RT-8-30): "While rst_ni = 0, o_d_valid, o_alert, o_alert_integ_fail and o_intr_timer_expired shall be 0; o_a_ready is not checked." rules.json RT-2-04: "While rst_ni is 0, every register holds its reset value". spec:548 (RT-2-03): rst_ni "asserted asynchronously and released synchronously". contract.json:344 (CHK-006): "At every rising edge (and at any other sample point) where rst_ni=0: o_d_valid=0, o_alert=0, o_alert_integ_fail=0 and o_intr_timer_expired=0." |
| RTL does | All state uses `always_ff @(posedge clk_i or negedge rst_ni)` (e.g. prim_alert_receiver.sv:255-267, prim_diff_decode.sv:233-241, tlul_adapter_reg.sv:169-173). The sender's alert pair resets to {n,p}=2'b10 (prim_alert_sender.sv:271, 149-150), and the receiver's ack/ping pairs reset to 2'b10 (prim_alert_receiver.sv:118-140). If no reset event has reached these flops at the time-0 rising edge, they hold the simulator's initial value. Verilator's default 2-state init is 0, so alert_p=alert_n=0. The prim_xnor2 sigint (prim_diff_decode.sv:217-223, prim_xnor2.sv:13) is then 1. receiver state_q=0 (Idle) is not InitReq, so prim_alert_receiver.sv:245-250 drives integ_fail_o=1 combinationally, and that is wired to o_alert_integ_fail (ot_rv_timer_nnc.sv:111). o_d_valid (outstanding_q=0), o_alert (level_q=0) and o_intr (intr_o=0) would be 0. So the likely nonzero output at @0 is o_alert_integ_fail. The log does not say which output failed, so this is inferred. After the first clock edge with rst_ni=0 the flops reset and the check passes for every later reset (all mid-simulation resets in CHK-015/016/030/regression pass). |
| Test does | Checker verif/sva/nnc_chk_reset.sv:36: `assert property (@(posedge clk_i) !rst_ni |-> (o_d_valid==0 && o_alert==0 && o_alert_integ_fail==0 && o_intr_timer_expired==0))` with no exclusion of time 0.
