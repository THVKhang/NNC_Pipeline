## 1. Write beats were issued one beat ahead / Beat ghi bị phát sớm một beat — FIXED

| | |
|---|---|
| Symptom | Every AXI write went to APB at AWADDR + size for beat 0 (e.g. AWADDR 0x3000, 4 beats → PADDR 0x3004…0x3010; the last one outside the burst). Reads were correct. |
| Specification | REQ-IF-002 and OP-002; the spec's own waveform WF-005 (upstream `figures/wf-005.json`): AWADDR 0x2000, AWLEN 1 → PADDR **0x2000, 0x2004**. |
| RTL (delivered) | `m_axi2apb_wr_seq.sv:344` updated `reg_wr_addr <= w_wr_nxt_addr` when it captured the W beat, before `o_req_addr` sent that beat. The read sequencer advances after the beat (`m_axi2apb_rd_seq.sv:374-378`). The same line is in upstream `rtl_v2/`. |
| Found by | the independent SVA checker CHK-016 and 12 cocotb tests; the triage agent traced all 12 analysed failures to this line and judged *A: RTL wrong*. |
| Fix | [wr_addr_advance.diff](wr_addr_advance.diff), now applied to `../rtl/` (recorded in [../NOTICE.md](../NOTICE.md)): the address advances when the beat's APB response returns (`ENUM_ST_WAIT && i_rsp_valid`). Checked first on a copy with `nnc inject` ([results.json](results.json): 14/15, 0 assertion failures), then in the full flow. |

## 2. Arbitration after a lone transaction / Phân xử sau một giao dịch đơn lẻ — DECIDED: round-robin

| Reading | Next winner after "lone write, then AR and AW together" | Followed by |
|---|---|---|
| REQ-FUNC-003 word for word: AR wins the first tie after reset, the preference flips after each completed transaction | AW | the first contract and test |
| Round-robin: the side served last gets lower priority (`m_axi2apb_apb_ctrl.sv:216-226`) | AR | the RTL |

Decision (Gate 1, rules.md question 2, recorded on delegation): **round-robin**, which matches the RTL. CHK-019 and CHK-031 in the contract were updated, G2 re-approved, and the test regenerated by the test writer (which never sees the RTL). The RTL arbitration is unchanged.

Quyết định: **round-robin** (khớp RTL). Contract CHK-019, CHK-031 được cập nhật, G2 duyệt lại, test được sinh lại. Logic phân xử trong RTL không đổi.

## 3. Test-bench defects found after the fixes / Lỗi testbench phát hiện sau khi sửa — FIXED

- **Reference model missed writes cut by reset.** On the fixed RTL one test still failed: `test_chk_031_reset_mid_transaction`, memory byte 0x7503 = 0x81, model 0x22. Triage judged *B: test wrong* ([triage_chk031_reset.md](triage_chk031_reset.md)): the bridge writes APB one beat at a time and nothing is rolled back on reset (spec:163, 333, 584), but the reference model only recorded a write when its B response arrived. The fix records, for an aborted write, every APB beat that had completed, with the same pwdata/pstrb = W-beat check; the final memory comparison stays byte-exact. G3 re-approved with that note.
- **Hang in the helper library.** The regenerated test awaited the value returned by `start_clock()`; in cocotb 2.1 that is the clock's never-ending task, so every test hung. `start_clock()` (nnc/simlib) now returns nothing. The test itself was not changed for this.
