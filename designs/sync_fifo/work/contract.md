## Assumptions

- This simulation is CFG-BASE: PARA_SFIFO_DEPTH=8, PARA_SFIFO_DATA_W=32, PARA_SFIFO_PTR_RETIME=0, PARA_SFIFO_MEM_USE_MACRO=0, so i_full_thr and i_empty_thr are 4 bits wide (LPARA_OCC_W=clog2(9)).
- Clock periods are not parameters: each test picks its clock periods from one generator. A test that uses several ratios changes them only while both hardware resets are asserted.
- i_full_thr and i_empty_thr count as 'not in use' while both hardware resets are asserted, so the threshold sweep changes them only then.
- Testbench inputs (i_wr_en, i_wr_data, i_rst_n_sw, i_rd_en) change just after a rising edge of their own clock. Checkers sample the values just before each rising edge; at coincident edges they use pre-edge values.
- o_sw_rst_busy is 1 exactly in the cycles in which the write reset FSM is not in RUN. Because the request rises with busy and the read FSM returns to RUN before the write FSM leaves REL, every read-side block interval lies inside an o_sw_rst_busy=1 interval. CHK-003 and CHK-005(b) rely on this; it is derived from Sections 10.1, 10.6, 10.7 and 14.2.1.
- i_rst_n_sw is held at 1 while the hardware resets are asserted in the reset tests, so the reset values o_full=0 and o_full_thr=0 are not masked by the block term.
- The specification gives no exact length for the software reset sequence ('a few cycles'), so a bounded wait of 64 write cycles is used for o_sw_rst_busy to fall.
- The two hardware resets are always asserted together, as required by REQ-RESET-002.
- DEC-021 (no full-FIFO bypass) is verified as written. Its confirmation by the designer is still an open item of the specification.
