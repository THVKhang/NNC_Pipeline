## Assumptions

- D denotes PARA_SPI_CLK_DIV. A command handshake (acceptance) at rising edge E means i_rst_n=1, i_cmd_valid=1 and o_cmd_ready=1 in the cycle ending at E; the checker captures i_cmd_data, i_cmd_last there, and if o_cs_n=1 in that cycle it is a burst start and CPOL_b=i_cpol, CPHA_b=i_cpha are captured from the same cycle.
- 'Cycle starting at edge E' means values observed after E has settled (sampled before the next rising edge, e.g. at the falling edge); 'cycle ending at E' means values sampled just before E. Testbench drives inputs at falling edges of i_clk unless a test says otherwise.
- The interface-level checker models transfer phases (lead, transfer, Pause, Trail, Idle gap) and the expected received byte from i_miso at sampling edges using only port values and PARA_SPI_CLK_DIV; all checker state is cleared while i_rst_n=0.
- Per the designer decision, i_rst_n is asserted and released at falling edges of i_clk; CFG-MAX tests use bursts of at most 2 bytes and long waits are expressed as multiples of 16*D, capped to keep run time bounded.
- Coverage items of VER-011 are collected inside the listed tests; each test is run in each configuration CFG-BASE, CFG-MIN, CFG-MAX through run_set.json.
