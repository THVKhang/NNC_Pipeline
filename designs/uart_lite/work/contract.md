## Assumptions

- Timing notation: 'edge E' is a rising edge of i_clk. A value 'at E' is the value sampled just before edge E. 'Becomes X at edge E' or 'in the cycle after E' means the value is sampled as X at edge E+1.
- s(E) is the value of i_rxd sampled at rising edge E. The testbench changes i_rxd only at falling edges, so s(E) is well defined. The 2-edge synchronizer latency is accounted for by the spec's V=M+2 (D-003).
- RX reference model: R1 is the first rising edge with i_rst_n=1 after a release, and s(R1-1)=1. When idle, the start edge T0 is an edge with s(T0-1)=1 and s(T0)=0. At T0+H (H=floor(N/2)), s=1 means a glitch and a return to idle. Otherwise data bit i = s(T0+H+(i+1)N), M=T0+H+9N, the receiver is idle from M on (a start can be detected at M+1), and V=M+2 with load, take or drop as in Sections 7.6 to 7.8. Asserting i_rst_n clears all model state, including a frame that has passed M but whose V has not been reached yet.
- TX reference model: E0 is an edge with i_tx_valid=1, o_tx_ready=1 and i_rst_n=1 sampled. D is i_tx_data sampled at E0. The frame occupies the samples at E0+1 to E0+10N. Asserting i_rst_n clears the model.
- Section 8.5 (loopback latency) is not in the rule set. The expected loopback latency V=E0+H+9N+3 is derived from REQ-TX-010, REQ-RX-003 and D-003, using the half-cycle (falling-edge) loopback delay set by the designer decision.
- Unless a test says otherwise, it runs with the default PARA_UART_CLKS_PER_BIT=16 (H=8), and all assertion groups (reset, tx, rx, gen) are active in every test and configuration.
