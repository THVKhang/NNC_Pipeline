# Formal counterexample triage — async_gray_fifo

Counterexamples analysed: 2. Causes: A = RTL wrong, B = checker wrong, C = specification unclear, E = an environment obligation missing from verif/formal/nnc_env.sv. The designer decides; nothing was changed.

## CHK-003 (a_CHK_003, verif/sva/nnc_chk_rd.sv:73-77) — most likely **B_checker_wrong**

| Part | Content |
|---|---|
| What happens | Both domains come out of reset (wr at step 1, rd at step 2). Two writes are accepted (write edges at steps 3 and 6), so wbin=2. One read is accepted at read edge 8, so rbin=1 and rgray=1. Then i_rst_n_wr alone goes low at steps 9-10 while i_rst_n_rd=1 (a one-domain hardware reset after the FIFO was used). This sets the write pointer and wgray to 0, but the read pointer stays at 1. At read edge 10 the write-pointer synchronizer still holds the old Gray value 3 (wbin_s=2, occupancy 1). At read edge 12 the synchronizer has flushed to 0, so wbin_s=0 and rbin=1. The 4-bit occupancy is 0-1 = 15. o_empty=0 because rgray(1) != wgray_s(0), and o_empty_thr = (15 <= 14) = 0. Columns 12-13 show o_empty=0, o_empty_thr=0 with i_empty_thr=14. Read edge 14 samples this state and part (b) fails (i_empty_thr >= 8 requires o_empty_thr=1). i_rst_n_wr is asserted alone again at step 12, and the two resets first overlap at step 14. So by the env's own bookkeeping (r_dirty/r_ovl, nnc_env.sv:90-104) the failing state lies inside the window after a one-domain reset. Note on timing: in this trace a register clocked at step k takes the inputs of column k-1, and a release edge still samples reset low (ENV-05/06). That is why o_sw_rst_busy stays 0 at step 11. |
| Specification says | REQ-FUNC-010 (spec/AsyncGrayFIFO_Design_Specification.md:139): "`o_empty_thr` shall be 1 when the read-domain occupancy estimate is less than or equal to `i_empty_thr`. The occupancy estimate is the binary write pointer minus the binary read pointer, where the pointer of the other domain is the synchronized one ... Every value of `LPARA_PTR_W` bits is accepted; the comparisons are defined for all of them". DEC-006 (spec:1473, rules.json AF-20.2-06 :10175) gives the same formula. Spec 7.2 (spec:424, rules.json AF-7.2-12 :4113): "If only one domain is reset after the FIFO was used, the pointer state of the two domains becomes inconsistent. The IP neither detects nor repairs this (ASM-005)." ERR-003 (spec:1099, AF-12-07 rules.json:7813): "Reset asserted in one domain only, after the FIFO was used; FIFO state inconsistent; not detected ... Reset both domains; Integrator responsibility". ASM-005 (spec:1461, AF-20.1-05 rules.json:9990): "No FIFO operation (write or read) starts before both domains have left reset. Consequence, not a requirement: if one domain is reset alone ... the pointer state ... becomes inconsistent". DEC-009 (spec:1476) and AF-7.2-11 (rules.json:4088): "The two hardware resets are independent inputs and need not be asserted together". Contract CHK-003 (contract.json:287) requires (b) at every read edge, with no exception for this inconsistent state. Contract CHK-023 (contract.json:757-758) drives one-domain resets on purpose as legal stimulus. |
| RTL does | rtl/m_vlsit_afifo_rd.sv:112 `assign w_occ = w_wbin_s - reg_rbin;` (4-bit modulo). Line 118: `assign o_empty_thr = w_rd_blk ? 1'b1 : (w_occ <= i_empty_thr);`. Line 97: empty = (reg_rgray == w_wgray_s). reg_rbin/reg_rgray are reset only by i_rst_n_rd (lines 133-146). The write-pointer synchronizer is also reset only by i_rst_n_rd (lines 205-215). So a write-only reset makes the estimate wrap to 15. The RTL computes exactly the REQ-FUNC-010 formula on the estimate. |
| Checker does | verif/sva/nnc_chk_rd.sv:73-77: `@(posedge i_clk_rd) 1'b1 |-> ((!o_empty || o_empty_thr) && (i_empty_thr < PARA_AFIFO_DEPTH || o_empty_thr) && (i_empty_thr != 0 || (o_empty_thr == o_empty)))`. It has no disable iff and no qualification for the inconsistent state after a one-domain hardware reset. Part (b) relies on the estimate being at most DEPTH, which holds only while the pointers are consistent. The env tracks this window in w_rst_pend (verif/formal/nnc_env.sv:90-114) but uses it only to block i_wr_en/i_rd_en (ENV-07/08). The checker does not use it. |
| B_checker_wrong | For: The violation needs a hardware reset of only the write domain after the FIFO was used (steps 9-10, read domain still running). The spec says this leaves the pointers inconsistent and not repaired (AF-7.2-12 rules.json:4113, AF-12-07 :7813, ASM-005 spec:1461), so it promises no flag behavior in that state. The RTL follows the REQ-FUNC-010 formula exactly (m_vlsit_afifo_rd.sv:112,118); the estimate just wraps to 15. Part (b) of the assertion assumes the estimate is at most DEPTH. Parts (a) and (c) still hold (equal Gray pointers mean occupancy 0). The env already models the pending one-domain-reset window (nnc_env.sv:90-114), but the checker ignores it.<br>Against: Contract CHK-003 (contract.json:287) says "At every rising edge of i_clk_rd" without an exception. REQ-FUNC-010 (spec:139) says every threshold value is accepted and the comparisons are defined for all of them. Read on its own, that supports an unconditional check. |
| C_spec_unclear | For: REQ-FUNC-010 (spec:139) states the threshold behavior unconditionally, with examples such as "a value above the depth makes it never 1" on the full side. The spec never says whether threshold guarantees are suspended in the inconsistent state of ERR-003 / AF-7.2-12. The contract (contract.json:287) did not carve out that window either.<br>Against: ERR-003 (spec:1099) and spec 7.2 (spec:424) say plainly that the FIFO state is inconsistent and not detected after a one-domain reset. Reading the threshold flags as exempt is the natural reading, so the spec is not seriously ambiguous. |
| E_environment_missing | For: The trace needs a one-domain hardware reset after use. One could add an assumption forbidding resets that do not overlap.<br>Against: The spec places no such obligation on the environment. ASM-005 calls the inconsistency a "Consequence, not a requirement" (spec:1461), and DEC-009 / AF-7.2-11 say the resets are independent and need not be asserted together (spec:1476, rules.json:4088). Contract CHK-023 parts 2/3 (contract.json:757-758) use one-domain resets as legal stimulus, and the nnc_env.sv header (lines 37-38) says resets asserted at any moment are legal. An assume that forbids them would be stronger than the spec and could hide real bugs. |
| A_rtl_wrong | For: One could argue that i_empty_thr >= DEPTH should force o_empty_thr=1 whatever the pointer state, for example by saturating the estimate.<br>Against: The RTL implements the REQ-FUNC-010 / DEC-006 formula exactly (m_vlsit_afifo_rd.sv:112,118). The spec says the IP neither detects nor repairs the one-domain-reset inconsistency (AF-7.2-12), so no clamping is required. In every consistent state the estimate is 0..8 and (b) holds. |
| Options | (1) B, preferred: qualify the parts of a_CHK_003 that depend on the occupancy range (part (b); (a) and (c) can stay unconditional). Disable them from the assertion of a reset of one domain only until both domains have been reset with overlapping windows and released. Use the same r_dirty/r_ovl/w_rst_pend tracking as nnc_env.sv:90-104, copied into the checker or exported from the env. Also record the exclusion in contract CHK-003 with references to AF-7.2-12 / AF-12-07 / ASM-005. (2) C: ask the spec owner to state in REQ-FUNC-010 or ERR-003 whether the threshold flags have any guaranteed value after a one-domain reset. If the answer is yes (for example a clamped estimate), the case becomes A and the RTL needs a saturated estimate in m_vlsit_afifo_rd.sv:112-118. (3) An env assumption forbidding one-domain resets is not supported by the specification (DEC-009, ASM-005 'not a requirement', CHK-023), so it is not recommended. |

## CHK-013 (a_CHK_013, verif/sva/nnc_chk_wr.sv:123-129) — most likely **B_checker_wrong**

| Part | Content |
|---|---|
| What happens | i_full_thr=8 (equal to DEPTH) from step 1. One write is accepted at write edge 3 (wbin=1) and one read at read edge 8 (rbin=1, rgray=1). At step 8 i_rst_n_wr alone goes low while i_rst_n_rd=1. This one-domain hardware reset sets wbin/wgray and the read-pointer synchronizer to 0, and the release edge 9 still samples reset. Write edge 11 loads stage 1 of the synchronizer with rgray=1. At step 11 i_rst_n_rd alone goes low; i_rst_n_wr is high, so the windows do not overlap yet. Write edge 13 moves the stale value 1 to the synchronizer output, so rbin_s=1 while wbin=0. The 4-bit write-domain estimate is 0-1 = 15. o_full=0 (wgray 0 != rgray_s^1100), and o_full_thr = (15 >= 8) = 1. Columns 13-14 show o_full=0, o_full_thr=1 with i_rst_n_sw=1, o_sw_rst_busy=0, i_rst_n_wr=1. Part (c) fails: with i_full_thr==DEPTH it requires o_full_thr == (o_full && i_rst_n_sw && !o_sw_rst_busy) = 0. Write edge 15 samples column 14 (at step 15 both resets are low, which is the first overlap). The failing state lies inside the window after a one-domain reset tracked by nnc_env.sv:90-104. |
| Specification says | REQ-FUNC-010 (spec:139): "`o_full_thr` shall be 1 when the write-domain occupancy estimate is greater than or equal to `i_full_thr`. The occupancy estimate is the binary write pointer minus the binary read pointer, where the pointer of the other domain is the synchronized one ... it is pessimistic for the full side (it can be larger than the true occupancy)". Port table AF-6.2-18 (rules.json:3160): "Occupancy estimate is greater than or equal to i_full_thr". DEC-006 (spec:1473, AF-20.2-05 rules.json:10148). Spec 7.2 (spec:424, AF-7.2-12 rules.json:4113): "If only one domain is reset after the FIFO was used, the pointer state of the two domains becomes inconsistent. The IP neither detects nor repairs this (ASM-005)." ERR-003 (spec:1099, AF-12-07 rules.json:7813): "FIFO state inconsistent; not detected ... Reset both domains ... Integrator responsibility". ASM-005 (spec:1461): "Consequence, not a requirement". DEC-009 (spec:1476): the resets "need not be asserted at the same time". Contract CHK-013 (contract.json:524) requires (c) and (d) at every write edge with i_rst_n_wr=1, with no exception. |
| RTL does | rtl/m_vlsit_afifo_wr.sv:120 `assign w_occ = reg_wbin - w_rbin_s;` (4-bit modulo). Line 126: `assign o_full_thr = w_wr_blk ? (i_full_thr == '0) : (w_occ >= i_full_thr);`. Line 106: full = (reg_wgray == w_rgray_s ^ LPARA_FULL_MSK). reg_wbin/reg_wgray (lines 141-154) and the read-pointer synchronizer (lines 233-242) are reset only by i_rst_n_wr. The read pointer that crosses over is reset only by i_rst_n_rd (m_vlsit_afifo_rd.sv:133-146). A write-only reset therefore leaves the stale rgray=1 in flight, and the estimate becomes 15. The RTL computes exactly the REQ-FUNC-010 formula. |
| Checker does | verif/sva/nnc_chk_wr.sv:123-129: `disable iff (!i_rst_n_wr) 1'b1 |-> (((i_full_thr != 0) || o_full_thr) && ((i_full_thr <= DEPTH) || !o_full_thr) && ((i_full_thr != DEPTH) || (o_full_thr == (o_full && i_rst_n_sw && !o_sw_rst_busy))) && (!(o_full && i_rst_n_sw && !o_sw_rst_busy) || (o_full_thr == (i_full_thr <= DEPTH))))`. Parts (b), (c) and (d) assume the estimate is in 0..DEPTH, so that estimate >= DEPTH is the same as full. Nothing excludes the inconsistent window after a one-domain hardware reset. The env's w_rst_pend (nnc_env.sv:90-114) is used only for ENV-07/08 access blocking. |
| B_checker_wrong | For: The failure needs a write-only hardware reset after one write and one read (step 8, with i_rst_n_rd=1). It is followed by a read-only reset at step 11 that does not overlap the first one. That is exactly the ERR-003 / AF-7.2-12 inconsistent state, which the spec says is not detected or repaired. The RTL follows the REQ-FUNC-010 formula (m_vlsit_afifo_wr.sv:120,126); the estimate wraps to 15. Part (c), and parts (b)/(d), turn the formula into 'o_full_thr == o_full', which is valid only while the pointers are consistent. The env already tracks the window (nnc_env.sv:90-104), but the checker does not.<br>Against: Contract CHK-013 (contract.json:524) is written for every write edge with i_rst_n_wr=1 and has no exception. REQ-FUNC-010 (spec:139) says "a value above the depth makes it never 1" without a qualifier. |
| C_spec_unclear | For: REQ-FUNC-010 (spec:139) states the threshold semantics unconditionally. The spec never says explicitly that the threshold flags are undefined in the ERR-003 state. The contract did not derive an exception.<br>Against: Spec 7.2 (spec:424), ERR-003 (spec:1099) and ASM-005 (spec:1461) say together that the pointer state is inconsistent and not repaired. The flags are defined as functions of those pointers, so any guarantee lapses. |
| E_environment_missing | For: Forbidding resets that do not overlap would remove the trace.<br>Against: The spec makes this no environment obligation. ASM-005 calls the one-domain-reset inconsistency "Consequence, not a requirement" (spec:1461). DEC-009 / AF-7.2-11 say the resets are independent (spec:1476, rules.json:4088). Contract CHK-023 (contract.json:757-758) drives one-domain resets on purpose, and the nnc_env.sv header (lines 37-38) declares them legal. Such an assume would be stronger than the spec. |
| A_rtl_wrong | For: With i_full_thr==DEPTH, the RTL raises o_full_thr while o_full=0, which a reader might take as an optimistic threshold flag.<br>Against: The value follows the specified formula: estimate (15) >= i_full_thr (8) (m_vlsit_afifo_wr.sv:120,126; REQ-FUNC-010 spec:139). The estimate is out of range only because of the inconsistency, which the spec explicitly does not repair (AF-7.2-12). In consistent operation the estimate is <= 8, and o_full_thr with thr=8 equals o_full (outside the software-reset block). |
| Options | (1) B, preferred: gate parts (b), (c) and (d) of a_CHK_013 (part (a) can stay) with a 'pointers consistent' qualifier. That qualifier is false from the assertion of a reset of one domain only until both domains have been reset with overlapping windows and released (the r_dirty/r_ovl/w_rst_pend logic of nnc_env.sv:90-104, copied into the checker or shared). Add the exclusion to contract CHK-013, citing AF-7.2-12 / AF-12-07 / ASM-005. Apply the same qualifier to CHK-003 part (b) for consistency. (2) C: ask the spec owner whether REQ-FUNC-010 guarantees anything after a one-domain reset. If it must (for example 'never 1 above depth' unconditionally), it becomes A and the RTL estimate in m_vlsit_afifo_wr.sv:120-126 needs saturation or range handling. (3) Do not add an env assumption forbidding one-domain resets: DEC-009, ASM-005 and CHK-023 do not support it. |
